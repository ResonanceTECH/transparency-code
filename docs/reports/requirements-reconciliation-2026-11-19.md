# Сверка требований и реализации · обновлено 20.11.2026

## Основание и границы

Учтены оба предоставленных документа: `Функции_проверяющего_+_правки_в_интерфейс.docx` и `Роли и функции + ввод данных (4).docx`. Более поздние уточнения применены к ролям: реестр — стартовый экран, сигналы — вопросы для человека, решение о назначении — вне платформы.

Целевая сборка — **`fullstack/`**. Оставлен один текущий финансовый профиль с постоянным серверным хранением на `/` для всех ролей; `/prototype` — совместимая ссылка на него. Прежний frontend дел/документного анализа удалён, его backend и данные сохранены. Исходники Дарьи, соседние экспорты, GitHub и удалённый сервер не заменены.

Это учебный контур, а не заявление production-соответствия всей системы. Подлинность подписи, правовую применимость и читаемость оригиналов оценивает человек.

## Общие и ролевые требования

| Требование | Реализация |
|---|---|
| Настоящие аккаунты и роли | `/api/auth/*`; профиль владельца, назначенные материалы reviewer/specialist, проверка роли и аккаунта на сервере |
| Постоянное сохранение | типизированный `questionnaire-v1`, файлы в `UPLOAD_DIR`, версии/оценки/сообщения/аудит в БД |
| Только готовая отправка | семь групп, обязательные поля/доступные файлы и отдельное подтверждение; сервер повторяет проверку |
| Подписанный скан согласия | отдельный файл вида consent, обязателен; галочка передачи его не заменяет; наличие подписи проверяет специалист |
| Приватный черновик | отдельные личные поля/пояснение/аудит; reviewer получает слепок версии, а не живой черновик |
| Только назначенные материалы | очередь, карточки, оригиналы, решения, сообщения, аудит и export требуют сохранённого назначения; specialist не обходит его |
| Пустой старт без статических соседей | на чистой БД нет материалов/счётчиков; сохранённые назначения не стираются при новом входе |
| Независимый демо-комплект | явная серверная операция с отдельным владельцем; не читает профиль reservist; личный импорт — только в нетронутый профиль |
| Контакты | ФИО/телефон/email из версии в карточке, контакты операторов из API внизу обоих кабинетов, пометка «вымышлены» |
| Принятие, уточнение, снятие, завершение | выбор человеком с комментарием; серверная статус-машина, версия и обязательные условия итогового закрытия |
| Результат владельцу и завершение работы | итог, комментарий, основание и файл доступны владельцу; закрытый материал не редактируется |
| Комментированные сигналы | включение/рассмотрение/исключение/уточнение append-only, не без комментария, не для старой версии |
| История и аудит | private/submitted, версии, загрузки/доступ к оригиналам, изменения, комментарии, статусы, просмотры/печать; reviewer не получает private |
| Без автоматического отказа/исправления | дубль не удаляется, сумма не вычитается, основание компенсации не заменяется, плохой скан сам не снимает профиль |
| Нет внешнего ответа ≠ нет выплат | внешние источники не симулируются; ручная загрузка и «сведения не получены» не подменяются отрицательным результатом |

## Поля и исключения

Личность и программа: ФИО, год рождения, место/статус работы, телефон, email, период, поток, год, регион, организатор, диплом и акт с реквизитами/файлами. Предполагаемый орган и фото необязательны; распознавания лиц нет.

Служба: несколько периодов, организация, начало/окончание, вид и категория, включая волонтёров. Родство: предусмотренные минимальные ФИО/степень/статус и отдельный ответ о выплатах, без медицинских сведений. Получатели-члены семьи — самостоятельные ФИО/родство/год рождения. Деятельность: несколько записей с организацией, видом, оформлением, периодом и основанием.

| Категория | Поля и документ |
|---|---|
| Денежное довольствие | период, плательщик, получатель, сумма, основание; приказ обязателен |
| Надбавки/дополнительные | вид, основание, период, плательщик, получатель, сумма; приказ обязателен |
| Единовременные | событие/дата, категория и ФИО получателя, сумма, плательщик, НПА/редакция, период, фактическое перечисление; файл при наличии |
| Федеральная/региональная/муниципальная поддержка | отдельные ответы уровней, орган/регион, наименование/необязательный код, дата, получатель, сумма и основание; файл обязателен |
| Страховые/компенсации | личные и за родственника отдельно, получатель/тип основания/дата/период/сумма; решение или справка обязательны |
| Пенсии/социальные | только «Да / Нет», без суммы и документа |
| Членам семьи за резервиста | связь с конкретным получателем, сумма/дата/основание/файл; не личный доход резервиста |
| Материальная помощь | назначение, организация, получатель, денежная/натуральная форма, сумма либо описание, основание и файл; натуральная не входит в денежный итог |
| Жильё | «Да / Планируется / Нет»; план — год и файл, «Да» — вид/основание/даты/файл; жильё и кредит не считаются денежным поступлением |
| Неденежные меры | описание, основание, файл при «Да», без прибавления к доходу |

«Нет» сохраняет скрытые данные в личном черновике, но не публикует их. Скрытые условные поля и удалённые строки также не восстанавливаются из legacy-метаданных в печати/слепке. Старые дополнительные сведения и родственники сохраняются отдельно без урезания канонических строк или округления денег; SQL-поля остаются совместимой проекцией.

Банковские выписки и подробный профиль родственника не запрашиваются. Загрузчик не способен определить назначение произвольного файла по его содержанию; ограничение объясняется пользователю, проверку проводит человек.

## Сигналы, файлы и итог

Три вопроса по **введённым сведениям**: `РО-01` (получатель/основание компенсации), `ДУ-01` (возможное повторное назначение), `ДЕ-01` (пересечение периодов службы/деятельности). Это не OCR и не выдуманные цитаты из PDF. Поздняя дата перечисления не равна периоду основания и сама по себе не означает нарушение.

Файл ограничен 5 МБ, разрешённым форматом и признаками контейнера; изображения дополнительно декодируются. PDF/DOCX не проходят полноценную проверку целостности/подлинности, антивирус или автоматическую оценку читаемости. Оригинал хранится отдельно с неизменным ID; новая загрузка не наследует старую оценку. При недоступном оригинале интерфейс обозначает проблему, сервер запрещает представить/закрыть неполный материал.

Ручные оценки: пригоден, нужна конкретика, нечитаемый/неполный скан; всегда с комментарием и конкретной версией. Запрос уточнения — отдельное явное действие. Для итогового статуса сервер требует три подтверждения, комментарий ≥10 символов, реквизиты ≥5, доступный файл результата текущей версии, терминальные комментированные решения сигналов и пригодные комментированные оценки всех не-фото приложений.

## Печать и библиотека

Единая A4 включает **все разделы**, ответы/записи десяти категорий, получателей, деятельность, приложения/согласие, пояснение и отсутствующие сведения. Владелец может печатать неполный черновик; проверяющий — только представленную версию, в том числе историческую. Печать и скачивание не отправляют черновик.

Шаблоны: пустая анкета, лист описания выплаты и памятка по скану. Каждый печатается отдельно без персональных данных; ни один не становится представленным комплектом. Это не официальные формы, не форма согласия и не полный справочник региональных выплат. Действующие формы предоставляет оператор.

Четыре статических вымышленных PDF в `docs/examples/` сохранены с прежнего UI-этапа (7/5/1/1 страниц), а не заново сформированы из текущей серверной БД. Актуальную анкету следует печатать в интерфейсе; оригиналы не склеиваются, а перечисляются в реестре.

## Проверки этой итерации

| Проверка | Результат |
|---|---|
| `npm.cmd run typecheck`, `npm.cmd run build` | типизация и сборка клиента проходят |
| Ruff, `compileall` | статические проверки backend проходят |
| Импорт/ORM/OpenAPI | приложение и mapper configuration загружаются; 48 путей |
| Сохранённая SQLite-БД | резервная копия, подтверждённый baseline `e14c17090890`, миграция `c72f6a904e11` |
| Схема и прежние данные | `alembic check` без изменений, совпадение прежних колонок/строк 25 таблиц, integrity `ok`, FK-ошибок нет |
| Тесты/сценарии | **не запускались** по просьбе пользователя; никакие прежние числа тестов не применяются к новой интеграции |

Старый in-memory отчёт сохранён [в архиве](archive/requirements-ui-before-api-2026-11-19.md). Старые pytest/Playwright/capture/CI-шаблоны требуют обновления под новый контракт. Статическая проверка и сборка не являются подтверждением полного многопользовательского цикла или security-аудитом.

## Вне локальной доработки

1. Production-аудит, HTTPS и допуск к реальным ПДн с утверждённым согласием оператора.
2. Административная выдача аккаунтов/назначений; в учебном контуре отправка автоматически назначает первого reviewer.
3. OCR, антивирус, подпись/подлинность, ведомственные реестры и юридическая применимость.
4. Полная база региональных выплат, подбор НПА или официальных форм.
5. Запуск Docker/PostgreSQL в этой итерации, GitHub/GHCR, удалённое развёртывание и замена соседних копий.

Итог: требования профильного UI связаны с серверным хранением, контролем доступа, комплектностью и версионным человеческим рассмотрением. Не реализованные внешние возможности не имитируются.
