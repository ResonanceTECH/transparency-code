# Состояние клиента «Резонанс» · 19.11.2026

Актуально для локальной сборки `fullstack/`. Исходные копии в соседних папках и GitHub не синхронизировались.

## Два независимых интерфейса

| Маршрут | Код | Где хранятся сведения |
|---|---|---|
| `/prototype` | `frontend/src/profile/FinancialProfileGate.tsx` → `FinancialProfile.tsx` | Учётная запись из API; анкета, версии, вложения и журнал в памяти страницы |
| `/` | `frontend/src/app/`, в том числе `profile.tsx` | Запросы к `backend/app/domains/profile/` и другим доменам; БД и файловое хранилище |

Новые требования реализованы в `/prototype`. Разница между моделями не скрыта: согласие-скан, новые поля, оценки качества и единая печать не перенесены в серверный профиль. Для реальных пользователей необходим отдельный этап интеграции.

## Модули `/prototype`

| Файл в `frontend/src/profile/` | Назначение |
|---|---|
| `model.ts` | Черновик, CRUD, неизменные отправленные версии, статусы, оценки документов, решения сигналов, аудит, выбор источника печати |
| `fields.ts` | Единые описания полей для форм, проверки комплектности и печати; условные записи, даты и суммы |
| `editors.tsx`, `screens.tsx` | Управляемые формы и рабочие экраны обеих ролей |
| `documents.ts`, `ui.tsx` | Метаданные вложений, технические проверки, загрузка, просмотр и скачивание |
| `signals.ts` | Три детерминированных вопроса по введённым полям, без OCR и выдуманных цитат |
| `print.tsx`, `print.css` | Вся анкета A4 и три самостоятельных печатных шаблона |
| `FinancialProfile.tsx` | Оболочка, навигация, защита экранов, модальное окно, контакты и закрытое дело |

Демо-агрегат читается из `frontend/public/samples/profile.json` через небольшой virtual-module-плагин Vite; копии JSON в исходниках нет, прямой импорт статических public-URL не используется. Генератор `frontend/tools/generate_samples.py` создаёт 12 валидных синтетических PDF и два JSON только в этой frontend-копии.

## Резервист

- Редактируются личные сведения и программа, периоды службы, минимальные сведения о родственнике, получатели, все записи десяти категорий и дополнительная деятельность.
- Можно добавлять и удалять периоды, получателей, выплаты, деятельность и вложения. Удаление файла очищает ссылки черновика, но не отправленные версии.
- Ответ «Нет» скрывает условные поля. Пенсии — без документа; единовременные — документ при наличии; поддержка и планируемое жильё — обязательное основание.
- Есть необязательное фото, обязательный подписанный скан согласия и отдельное подтверждение передачи версии. Изменения черновика сбрасывают галочку передачи.
- Комплектность — **7 групп**, исходно **4/7**. Не хватает документа поддержки, предполагаемого года жилья и согласия. После дополнения — **7/7**, этап **90%**. Проценты 10/30/50/70/90 обозначают этапы, а не оценку дохода.
- Пояснение и исправления остаются личными до повторной отправки. «Подготовить версию» не удаляет дубли и не меняет основания самостоятельно.

## Проверяющий

- Стартовый экран — пустая очередь с четырьмя нулевыми счётчиками, поиском и фильтрами. Нет статических соседних дел. «Загрузить демо-комплект» читает отдельный исходный образец, не приватный черновик.
- Карточка содержит ФИО, телефон, email, период, статус, согласие и реестр представленных файлов.
- Документы оцениваются человеком с комментарием: «Пригоден для сопоставления», «Нужна конкретика», «Нечитаемый или неполный скан». Сохранение оценки не меняет статус автоматически; уточнение — отдельное действие.
- В «Карточке сигналов» доступны включение, рассмотрение, исключение и уточнение, всегда с комментарием. Решения привязаны к коду и номеру версии; архивная версия только для чтения.
- Рабочие статусы: «Принят к рассмотрению», «Требуются уточнения». Итоговые: «Снят с рассмотрения обоснованием», «Рассмотрение завершено». Для итоговых нужны проверки специалиста, комментарий, реквизиты и файл основания.
- После закрытия нельзя редактировать анкету, сохранять новые оценки или решения. Результат виден резервисту; решение о назначении остаётся вне платформы.
- Журнал проверяющего содержит только события представленного материала. Личные загрузки, самопроверки, изменения и пояснения до передачи не раскрываются. После выхода данные убираются из DOM.

## Печать и файлы

Единый документ содержит все актуальные поля, ответы, записи, сведения о получателях, деятельность, список вложений, согласие, пояснение и отсутствующие данные. Резервист выбирает черновик или последнюю отправленную версию; проверяющий — только отправленную. Реестр приложений не заменяет сами файлы.

PDF показывается во встроенном окне, PNG/JPG — изображением; DOCX честно предлагается скачать. Файлы с одинаковым названием имеют разные ID и сохраняют свои байты. Есть возврат фокуса, Escape и ограничение Tab в модальном окне.

При загрузке отсеиваются пустые файлы, размер больше 5 МБ, запрещённое расширение и явное несоответствие контейнера; изображения дополнительно декодируются. Это не антивирус, не полная проверка PDF/DOCX, не OCR и не проверка подписи.

CSP production-preview и nginx разрешают локальные/blob-превью. Приложение запрещено встраивать в чужой iframe; исключение same-origin ограничено учебными вложениями `/samples/`.

Исходная денежная сводка — **1 940 000 ₽** резервисту и **120 000 ₽** члену семьи отдельно. После явного удаления повторной записи — **1 790 000 ₽** резервисту. Натуральные, неденежные и жилищные меры автоматически не прибавляются.
