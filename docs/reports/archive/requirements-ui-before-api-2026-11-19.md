Более поздние уточнения о проверяющем применены к исходным ролям: очередь — стартовый экран, сигналы — вопросы для человека, решение о назначении — вне платформы. Соседние экспорты и исходники Дарьи не перезаписывались; действий с GitHub не выполнялось.

Не заявляется полное production-соответствие всей системы: `/prototype` — демонстрационная клиентская модель. Backend обеспечивает настоящий вход, но сохранение новых полей и оценок, обязательное согласие в API и серверная проверка назначений требуют отдельной интеграции. Отдельный маршрут `/` не заменён новым макетом.

UI-изоляция и local-аудит в макете — **не серверная защита реальных данных**. Все значения остаются в памяти одной учебной страницы; модель не предназначена для нескольких пользователей в отдельных браузерах.

## Поля резервиста и исключения

Личные сведения: ФИО, год рождения, место работы, статус, телефон, email, отчётный период. Программа: поток, год, регион, организатор, диплом и его реквизиты, акт о резерве и его реквизиты. Предполагаемый орган и фото необязательны, распознавания лиц нет.

Служба: несколько периодов с началом/окончанием, видом и категорией, включая волонтёров. Родственник: ФИО, степень и предусмотренный статус, без медицинских сведений и подробностей службы. Получатели — отдельные люди с ФИО, связью и годом рождения. Деятельность: организация, вид, оформление, период и основание; несколько записей.

| Категория | Поля и правила документа |
|---|---|
| 1. Денежное довольствие | Ответ, период основания, плательщик, получатель, сумма, основание; приказ обязателен |
| 2. Надбавки и дополнительные выплаты | Вид и основание, период, плательщик, получатель, сумма; приказ обязателен, дополнительное основание необязательно |
| 3. Единовременные выплаты | Наименование, событие и дата, категория/имя получателя, сумма, плательщик, НПА и редакция, период, фактическое перечисление; файл **при наличии** |
| 4. Федеральная/региональная/муниципальная поддержка | Отдельный ответ каждого уровня, орган/регион, наименование, необязательный код, дата, получатель, сумма и основание; файл **обязателен** |
| 5. Страховые и компенсации | Раздельные ответы и записи для личного участия и выплат за родственника; получатель, тип основания, дата, период, сумма, решение/справка обязательны |
| 6. Пенсии и социальные выплаты | Только «Да / Нет», **документ и сумма не запрашиваются** |
| 7. Членам семьи за резервиста | Связь с конкретным получателем из семейного списка, ФИО/год/родство, сумма, дата, основание и файл; не личный доход резервиста |
| 8. Материальная помощь | Назначение, организация, получатель, денежная/натуральная форма, сумма либо описание, основание и файл; натуральная не входит в денежную сумму |
| 9. Жилищные меры | «Да / Планируется / Нет»; для плана — предполагаемый год и обязательный файл; для «Да» — вид, основание, дата решения и приобретения, файл; кредит и предоставление не смешиваются с денежной выплатой |
| 10. Неденежные меры | Описание, основание и файл при «Да»; отдельный учёт без прибавления к денежному доходу |

Все видимые поля управляются состоянием, а не `defaultValue` или статическими карточками. Одинаковые определения `fields.ts` используются для формы, проверки и печати. Повторная самопроверка не перезагружает страницу и не теряет файлы. Ответ «Нет» скрывает неактуальные записи, а не стирает их из черновика.

Банковские выписки не запрашиваются; загрузчик не может определить содержание произвольного файла, поэтому запрет дополнительно объяснён в интерфейсе. Система не заявляет проверку счетов или подлинности документов.

## Сигналы и оценка качества

По введённым полям формируются три детерминированных вопроса:

- `РО-01`: запись «резервист за родственника» содержит основание «за личное участие».
- `ДУ-01`: совпадающий идентификатор назначения, сумма и период в разных категориях.
- `ДЕ-01`: период дополнительной деятельности пересекается с указанной службой.

Это не выводы из PDF: **OCR не выполнялся**, цитаты из документов не выдумываются. Сверка реального содержания, правовой применимости, получателей, периодов и неденежных мер остаётся за кадровым специалистом. Поздняя дата фактического перечисления сама по себе не считается выходом основания за срок службы. Дубли автоматически не вычитаются.

Файл проверяется на пустоту, лимит 5 МБ, разрешённое расширение и явные признаки контейнера; изображения дополнительно декодируются. Для PDF проверяются заголовок и маркер конца, для DOCX — признаки ZIP и основных частей. Страницы PDF не разбираются. Это **не полная проверка целостности, не антивирус и не оценка читаемости**.

Ручная оценка документа всегда сопровождается комментарием. Отмечаются пригодность, необходимость конкретики или нечитаемый/неполный скан. Оценка сохраняется для версии; новая загрузка или новая версия не наследует её автоматически. Запрос уточнения — отдельная кнопка, а не автоматическое следствие оценки.

## Единая печать и учебная библиотека

Кнопка «Печать» открывает единую анкету из **всех разделов**, а «Печать / сохранить PDF» — диалог браузера. В документе есть контакты, программа, служба, родство/получатели, десять категорий с записями, деятельность, документы/согласие, пояснение и отсутствующие поля. Личный черновик можно печатать неполным. Проверяющий не получает выбор приватного источника.

A4, поля 15 мм, интерфейсные панели скрыты в печати, строки и записи защищены от случайного разрыва. Оригиналы приложений остаются самостоятельными файлами, не склеиваются с анкетой. Подпись на распечатке не заменяет скан согласия.

Библиотека содержит пустую анкету, лист описания выплаты и памятку по качеству скана. Каждый шаблон печатается отдельно и не содержит данных кандидата. Это **учебные заготовки**, не официальная форма согласия, не НПА и не придуманный полный справочник выплат регионов. Действующие формы предоставляет оператор.

[Заполненный пример](../examples/whole-profile-a4.pdf) и [печатные шаблоны](../examples/) сохранены в `docs/examples/` исключительно на вымышленных данных.

## Что явно осталось вне этой доработки

1. Серверная интеграция новых полей, согласия, оценок и печати с `app/domains/profile/`; постоянное хранение и обмен между разными браузерами.
2. Административная выдача доступа руководителем/кадрами и production-проверки назначений для нового интерфейса.
3. OCR, проверка подписи/подлинности, антивирус, ведомственные реестры и юридическая оценка.
4. База всех региональных выплат, автоматический подбор применимого НПА или официальных форм.
5. Коммиты, загрузка на GitHub, сборка/публикация GHCR и замена соседних frontend-копий.

Итог: в `/prototype` реализован рабочий учебный цикл подготовки, печати, передачи и человеческого рассмотрения; ограничения полного серверного продукта сохранены явно, без имитации недоступных возможностей.
